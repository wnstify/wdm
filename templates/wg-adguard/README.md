**wg-adguard** pairs a [WireGuard](https://www.wireguard.com/) VPN server (via [wg-easy](https://github.com/wg-easy/wg-easy)) with an [AdGuard Home](https://adguard.com/en/adguard-home/overview.html) DNS resolver. Connect a device to the VPN and all of its traffic is encrypted to your server, while its DNS is resolved through AdGuard Home — so ad, tracker, and malware-domain filtering follows you onto any network. wg-easy gives you a web UI to add clients and download their configs or QR codes; AdGuard Home gives you a dashboard for filter lists, query logs, and per-client rules.

## Features

- **WireGuard VPN** — Fast, modern, encrypted tunnels with a friendly web UI
- **Network-wide DNS Filtering** — AdGuard Home blocks ads, trackers, and malicious domains for every tunnel client
- **Headless Setup** — wg-easy seeds its admin account and endpoint on first boot; no setup wizard
- **QR-Code Clients** — Add a client in the UI and scan the QR code on your phone
- **Hardened Containers** — `cap_drop: ALL` with only the minimum capabilities re-added, no-new-privileges, no `SYS_MODULE`
- **Low Footprint** — Both services idle well under their recommended memory bands

## Prerequisites

- Docker and Docker Compose
- **The `wireguard` kernel module loaded on the host** — see below
- External Docker network (wdm creates `vpn_net` with static IPAM at install)
- Reverse proxy (Caddy, Nginx, Traefik) for the two web UIs
- Inbound access to **UDP port 51820** for remote WireGuard clients

### Host prerequisite: load the WireGuard kernel module

WireGuard runs in the Linux kernel. The container does **not** get the `SYS_MODULE` capability (it is excluded from wdm's allow-list for security), so it cannot load the module itself — instead, the host kernel-module tree is bind-mounted read-only at `/lib/modules` and the module must already be loaded on the host:

```sh
sudo modprobe wireguard
```

To make it persist across reboots:

```sh
echo wireguard | sudo tee /etc/modules-load.d/wireguard.conf
```

Most modern Debian/Ubuntu kernels ship the module; if `modprobe` fails, install your distro's kernel headers/extras package. wg-easy will fail to bring up its interface on boot if the module is not loaded.

## Installation

This template is managed by **wdm** — wdm renders `docker-compose.yml.tmpl` and `.env.tmpl` into your stack directory, pre-creates the `vpn_net` network with its static subnet/gateway, and runs `docker compose up -d` at install time. `TZ` defaults to the host timezone. `WG_HOST` is the public hostname your clients dial (collected at install). `WG_EASY_PASSWORD` is generated by wdm. See the wdm documentation for the CLI surface; do not edit the rendered `.env` or `docker-compose.yml` by hand, since wdm regenerates them on update.

### First run

1. **wg-easy admin password.** wg-easy is headless: it creates the admin user `admin` on first boot using the generated password in `~/docker/wg-adguard/.env` (the `WG_EASY_PASSWORD` line). Open that file to read your password, then log in to the wg-easy UI at `http://127.0.0.1:51821` (or through your reverse proxy).
2. **Public WireGuard port.** The WireGuard listener (`51820/udp`) is published on **all interfaces** by design so remote clients can connect directly. Open/forward UDP 51820 at your firewall. This is the one deliberately public surface; both web UIs stay on localhost.
3. **AdGuard Home setup wizard.** AdGuard ships its **own** first-run wizard (wdm pre-seeds no admin account and no config). Open `http://127.0.0.1:3000` (or through your reverse proxy) and complete the wizard:
   - **Admin Web Interface** — keep the default port **3000**, listen on **All interfaces** (`0.0.0.0`).
   - **DNS server** — listen on **All interfaces** (`0.0.0.0`), port **53**. This is what tunnel clients query; it is reached through the VPN over `vpn_net` (AdGuard's fixed address is `10.0.0.100`, which wg-easy already hands clients as their DNS), so DNS is never published on the host.
   - Set an AdGuard admin username and password when prompted. AdGuard writes its config to the `adguard_conf` volume.
4. **Add clients.** In the wg-easy UI, create a client, then scan its QR code (or download the `.conf`) on your device. Its traffic now tunnels to your server and its DNS resolves through AdGuard.
5. **Front the UIs with a reverse proxy.** Both web UIs bind `127.0.0.1` only. wg-easy serves plain HTTP (`INSECURE=true`) so your reverse proxy terminates TLS; point one host at `http://127.0.0.1:51821` (wg-easy) and another at `http://127.0.0.1:3000` (AdGuard).

## Configuration

### Environment Variables

| Variable | Description | Default |
|----------|-------------|---------|
| `WG_HOST` | Public hostname remote clients dial for WireGuard | (required) |
| `WG_EASY_ADMIN_USER` | wg-easy web UI admin username (catalog-fixed) | `admin` |
| `WG_EASY_PASSWORD` | wg-easy web UI admin password (wdm-generated, in `.env`) | (generated) |
| `TZ` | Container timezone | host timezone |

AdGuard Home takes no environment configuration here — it is configured entirely through its first-run wizard and dashboard, which persist to the `adguard_conf` volume.

### Ports

| Service | Container | Host bind | Purpose |
|---------|-----------|-----------|---------|
| wg-easy | `51820/udp` | `0.0.0.0:51820` (public) | WireGuard tunnel listener |
| wg-easy | `51821/tcp` | `127.0.0.1:51821` | Web UI (front with a reverse proxy) |
| adguard | `3000/tcp` | `127.0.0.1:3000` | Setup wizard + admin UI |
| adguard | `53` | not host-published | DNS — reached through the tunnel via `10.0.0.100` |

### Security baseline

- **wg-easy** — `cap_drop: ALL`, re-adding only `NET_ADMIN` + `NET_RAW` (configure the wg0 interface, routes, and the iptables NAT/forward rules). The `wireguard` kernel module is host-loaded (see the prerequisite) and `/lib/modules` is mounted **read-only**; `SYS_MODULE` is never granted. `DISABLE_IPV6=true` keeps wg-quick from needing IPv6 NAT modules. `no-new-privileges`, `ipc: private`.
- **adguard** — runs as container root (the image ships no usable non-root user) under `cap_drop: ALL` + `no-new-privileges`, re-adding only `NET_BIND_SERVICE` (the binary's file capability for binding privileged port 53) and `DAC_OVERRIDE` (writing its data dirs). No `NET_*` beyond `NET_BIND_SERVICE`, no `SYS_*`.

### Networking

A single Docker network, `vpn_net`, with static IPAM (subnet `10.0.0.0/24`, gateway `10.0.0.1`): AdGuard at `10.0.0.100`, wg-easy at `10.0.0.2`. The network is **not** `--internal` — wg-easy routes client egress to the internet and AdGuard reaches its upstream resolvers. AdGuard's fixed `10.0.0.100` is what wg-easy hands clients as their DNS server, so tunnel DNS queries land on AdGuard without any host port.

### Data layout

| Volume | Mount | Contents |
|--------|-------|----------|
| `wg_easy_config` | `/etc/wireguard` | Server keys, `wg0.conf`, the wg-easy SQLite DB (clients, hashed admin credential) |
| `adguard_work` | `/opt/adguardhome/work` | Filter lists, query log, statistics |
| `adguard_conf` | `/opt/adguardhome/conf` | `AdGuardHome.yaml` (written by the wizard) |

All three are named volumes; wdm preserves them on remove (never `docker compose down -v`).

## Updating

wdm bumps the pinned image tags and recreates the stack on update. The named volumes — and therefore your WireGuard server identity, client list, and AdGuard configuration — survive a recreate. The `WG_EASY_PASSWORD` is `regenerable: false`: wdm reuses the existing value, so your login does not change on update.
